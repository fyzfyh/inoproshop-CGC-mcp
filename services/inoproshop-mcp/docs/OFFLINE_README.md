# PLC 智能工程助手｜客户使用与评估手册

**适用于 InoProShop · v2026.10.20.1 文档修订版**

本手册帮助工程负责人组织首次评估，也帮助工程师完成环境连接、只读体验和具备条件后的受控修改。软件功能与适配范围沿用 2026-10-20 版。

## 一、获取评估交付

本版通过定向评估方式提供。**[授权用户下载完整离线包](https://github.com/fyzfyh/inoproshop-CGC-mcp/releases/download/v2026.10.20.1/PLC-Engineering-Assistant-Offline-Windows-x64-20261020.1.zip)**，或前往[版本页获取说明与校验文件](https://github.com/fyzfyh/inoproshop-CGC-mcp/releases/tag/v2026.10.20.1)。私有下载页面需要获授权的 GitHub 账号；无法访问时，请联系向您提供本说明的交付方。

请与部署负责人明确本次评估的工程、任务和可用能力。建议先选一个可读取的 ST 程序，完成理解与定位，再选择一处范围明确的调整。

## 二、准备条件

| 准备事项 | 本次评估要求 |
|---|---|
| 使用环境 | Windows x64，选择可写的本地短路径，建议预留至少 3 GB 空间。 |
| 工程软件 | 已安装并授权的 InoProShop；当前验证版本为 1.10.0.3。 |
| 对话入口 | 已安装并配置好的 ohmypi；当前验证版本为 18.8.7。先确认可以正常对话。 |
| 模型服务 | 使用方已配置可用模型，并确认网络、账号及数据使用约定。 |
| 评估资料 | 有权限使用的工程副本；如需模板创建，另准备经部署负责人核实的参考工程。 |
| 修改与编译 | 在本机完成相应能力确认后开展；读取成功不代表修改与编译已确认。 |

完整离线包已包含本产品所需的运行依赖，无需另外准备这些依赖。它不包含 InoProShop、ohmypi、模型账号、模型权重或厂商工程模板。云模型对话仍需相应网络；完全断网使用需事先配置可用的本地模型。

## 三、三个阶段与完成判断

| 阶段 | 要完成什么 | 可以继续的依据 | 暂时受阻时 |
|---|---|---|---|
| 环境连接 | 启动产品并选定接入的工程环境 | 显示连接就绪，能够识别选定的工程 | 处理对应软件的启动提示，请部署负责人核对环境。 |
| 只读体验 | 理解程序、定位信息 | 返回真实内容、信息来源和读取范围 | 核对工程、程序名和可读取内容，不急于开展修改。 |
| 受控修改 | 在工程副本中预览、执行并验证一处变更 | 本机能力已确认，目标及范围清楚，编译与保存结果分别明确 | 保留当前工程与结果，由部署负责人检查条件或安排恢复。 |

模板创建还需有可用模板并完成实际控制器复核。缺少模板时可以继续其他已满足条件的评估任务。

## 四、首次连接

1. **完整解压**安装包到可写的本地目录。不要直接在压缩软件中运行，也不要只复制启动文件；运行期间保留整个解压目录。
2. 双击 **`Connect-Ino.cmd`**。等待准备完成，并处理 InoProShop 自身的授权、设备组件或启动提示。普通使用无需管理员权限。
3. 确认本次接入的 InoProShop 窗口。若此前手动打开的窗口尚未接入，入口可能另开窗口；原窗口保留，请使用本次明确接入的窗口。
4. 看到“连接已就绪，请在 IDE 打开工程”后，在该窗口打开选定的工程副本，再回到 ohmypi 提出任务。没有打开工程时，连接就绪仍是正常状态。
5. 需要修改和保存时，将评估副本放入解压目录中的 **`work/mcp_p0/projects`**；该目录首次启动后生成。部署负责人应确认本次允许使用的副本位置与本机能力。其他位置的选定工程可先做读取。

开始评估前，请在原工程中保留未保存修改。评估使用单独副本，避免切换或覆盖正在编辑的原工程。

## 五、首轮评估任务

### 任务 1：理解一个程序

**准备条件**：环境已连接，选定工程中存在可读取的 ST 程序。将下方程序名替换为实际名称。

> 读取当前接入工程的 PLC_PRG，解释程序逻辑和关键变量，注明说明对应的源码位置及未读取范围。先不要修改或编译。

**预期结果**：返回与选定工程一致的内容和位置，区分确定信息与仍需人工核查的问题。

**不能继续时**：先请求列出当前工程与程序对象，核对程序名称。无法读取的加密或图形内容由工程师另行核查，不以推测补全。

### 任务 2：定位一个变量或相关用法

**准备条件**：任务 1 已确认读取对象与来源，选定一个真实变量名。

> 查找当前选定工程中 MotorEnable 的相关文本和用法，列出位置与上下文，说明查找覆盖的内容。请区分文本命中与已确认的引用关系，先不要修改。

**预期结果**：命中内容可定位，覆盖范围和查找时依据的工程内容明确。没有命中时，应说明已查范围。

**不能继续时**：核对变量名与大小写，确认相关内容可读取。关系分析暂不可用时可先进行文本查找，但两类结果不能相互替代。

### 任务 3：验证一处受控修改

**准备条件**：部署负责人已确认本机修改与编译能力；使用允许位置的副本，基线条件满足，并明确要调整的 ST 程序与业务意图。

先请求预览：

> 在评估副本的指定程序中，对刚才说明的条件进行一处调整。先给出建议和修改差异，保留程序名称及其他逻辑，说明影响与前提，暂不应用。

核查建议符合任务后，再明确执行范围：

> 按刚才确认的范围应用到这份评估副本，完成编译，并分别说明修改、编译和保存结果。遇到异常请保留诊断和当前状态，说明是否已恢复及后续处理方式。

**预期结果**：实际变更与授权范围一致，编译结论有依据，是否保存单独说明。需要另存时明确副本位置。

**不能继续时**：能力未确认、工程版本变化、模板复核失败或结果无法确认时，保留当前材料并交由部署负责人处理。恢复具备条件时可还原受控变更；已有后续人工修改时需要先核查，不能覆盖新改动或重复执行未知结果的修改。

## 六、形成评估结论

工程负责人可按以下记录结束首轮评估：

| 记录项 | 需要确认的内容 |
|---|---|
| 任务结果 | 哪些程序理解、信息定位和修改任务已完成。 |
| 信息依据 | 结果是否与真实工程一致，来源与覆盖范围是否清楚。 |
| 工程复核 | 修改是否符合原定业务意图，编译、保存及恢复结果是否明确。 |
| 部署条件 | 本次确认的软件环境、工程副本位置、设备与模板条件。 |
| 后续事项 | 仍需验证的环境、未覆盖内容及需要工程师继续处理的问题。 |

本机编译通过是工程验证的一项结果。交付前仍需由工程师完成工艺复核、设备联调与现场运行确认。

## 七、日常使用与升级

以后仍双击同一个 `Connect-Ino.cmd`。可用环境会复用，打开或切换工程后，应重新确认当前目标，再提出任务。退出 ohmypi 后，相关后台组件与 InoProShop 可以继续运行，按正常流程保留工程修改。

需要升级时，等待正在进行的工作结束，在原 IDE 中保留未保存修改，将新版完整解压到新目录，再由部署负责人安排旧连接退出与新连接确认。保留旧目录、工程、自动保存及原有使用数据，不覆盖运行中的目录。结果尚未确认的修改需先处理，不能通过换目录重复执行。

本次文档修订不要求已部署用户迁移工程。已有版本可继续使用，可先阅读新版手册；新下载的副本按本机实际情况完成连接与能力确认。

## 八、常见问题

| 情况 | 建议处理 |
|---|---|
| 无法访问下载页面 | 使用获授权的 GitHub 账号；尚无权限时联系资料提供方。 |
| 找不到 InoProShop 或 ohmypi | 确认已经安装、授权并可正常使用，再由部署负责人核对路径和版本。 |
| 已连接但没有工程 | 在本次接入的 InoProShop 窗口打开选定工程，再请求列出工程与程序。 |
| 能读取，但不能修改或编译 | 检查工程副本位置、本机能力及当前工程条件；确认前继续只读体验。 |
| 没有可用模板或设备不符 | 由部署负责人准备并复核参考工程；不要猜测型号或替换控制器。 |
| 软件提示旧连接、端口占用或访问异常 | 保留现有工程和使用数据，交由部署负责人处理；不要删除数据或强制关闭其他进程。 |
| 修改失败或结果无法确认 | 保留诊断与当前副本，先确认执行结果和恢复条件，不重复提交同一修改。 |
| 模型不能回复 | 检查所选模型的配置、账号和网络；工程环境连接与模型服务可达分别确认。 |
| 需要提交问题材料 | 提供必要的现象与经核查的诊断信息；先确认是否包含工程源码、账号或其他保密内容。 |

部署负责人可通过 `Connect-Ino.cmd -Check` 进行只读连接检查。其他配置与恢复操作见维护资料，由具备权限的人员按现有流程处理。
