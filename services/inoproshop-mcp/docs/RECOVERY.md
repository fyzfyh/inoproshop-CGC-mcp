# 故障诊断与恢复手册

所有示例针对允许写入目录中的工程副本。恢复对象由工程、宿主实例、原生 GUID、检查点和内容哈希共同确定。聊天结束不取消已经受理的持久作业；先查询原作业，避免生成另一次修改。

## 先读取状态

用 `ino_get_operation(project_id, operation_id)` 查看原作业的 `state`、`checkpoint_id`、`stages`、`result` 和 `error`。查询工具成功只说明查到了记录，不说明编译或修改成功。

| 状态或结果 | 含义 | 下一步 |
|---|---|---|
| QUEUED / CHECKING / CHECKPOINTED | 尚可在原生写入前取消 | `ino_cancel_operation`；随后继续查询到终态 |
| APPLYING / READING_BACK / COMPILING / SAVING | 正在执行已受理工作 | 继续查同一作业；取消请求不会中止正在运行的原厂 API |
| COMPLETED，compile_status=passed | 该作业要求的编译验证已通过 | 仍分别检查 persistence_status 和 index_status |
| FAILED，edit_status=applied，persistence_status=save_failed | 内存修改已成功，保存失败 | 读取当前工程；选择新副本路径保存，或显式恢复检查点 |
| RESTORED | 候选失败或显式恢复后，受控源码已恢复 | 查看原候选失败诊断；不能把恢复成功报告为修改任务成功 |
| OUTCOME_UNKNOWN | 原生操作可能已经执行，响应或进程丢失 | 先对账；不得换幂等键重复写入/创建/保存 |
| NEEDS_RECOVERY | 自动恢复无法证明安全，或恢复仅部分完成 | 保留材料，检查人工后改、新引用、对象 GUID 与宿主绑定 |
| index_status=failed / stale | 工程修改与索引结果分开 | 只重建索引，不重新执行已经成功的修改 |

`strict` 要求基线通过；`repair` 可以处理已知失败的基线，但候选必须整体编译通过。本版不接受部分修复作为整体成功。编译异常、没有明确完成消息、编译期间源码变化均不能算通过。

## 同一宿主中恢复检查点

1. 通过 `ino_list_hosts` / `ino_list_projects` 确认仍为原宿主实例和绑定。不要仅凭窗口标题或文件名判断。
2. `ino_capture_snapshot(project_id)` 取得当前 `snapshot_id`，读取目标源码；检查点记录位于 `state/artifacts/checkpoint`，作业阶段和最新补偿状态存储在 SQLite。
3. 以原作业的 `checkpoint_id` 和刚捕获的 `expected_snapshot_id` 调用 `ino_restore_checkpoint`，使用新的恢复幂等键；恢复操作也返回持久 `operation_id`。
4. 恢复工具只接受受控对象仍等于检查点前值或本次候选后值。两对象流程先恢复调用者，再验证引用并删除记录的新增 GUID。删除已执行但响应丢失时，可在确认该 GUID 已不存在后继续核验，不重复删除。
5. 查询恢复作业终态。恢复后编译结果和错误集合必须匹配原始基线；坏基线恢复不要求错误数变为零。恢复只改变内存，是否另存由用户任务决定。
6. 恢复会使索引过期。重新采集快照，再调用 `context_index_snapshot` 并查询其作业终态；只有该索引作业通过后，才能报告索引已更新。单独另存副本可能改变路径和宿主绑定，也按此步骤更新索引。索引失败只重建索引，不重复保存或恢复。

若工具报告人工后改、新引用、新对象内容被编辑、重名对象 GUID 不同或创建归属未知，停止自动恢复。不要按名称删对象，不要手工把作业状态改成成功。保留原候选、失败诊断、检查点和当前快照，人工在 IDE 中核对并决定保留哪份内容。

## 服务或 IDE 重启

服务必须使用原 state 目录，并且每个目录只能启动一个控制进程。启动时账本将明确写入前的工作取消；只读编译/索引中断记失败；已经进入原生修改且没有完成记录的工作保留为 OUTCOME_UNKNOWN。不会自动重放写入。

IDE 重启、关闭重开或切换工程后，旧宿主/工程绑定失效。重新列出并选择工程得到新绑定，旧补丁仍不可直接应用。旧检查点不能仅凭相同路径自动转移到新实例；原作业证据保留，必要时人工对比新实例源码与检查点。用户在 IDE 中后续修改的内容不会被自动覆盖。

保存响应丢失时，目标文件可能已经存在。用原 `project_id` 和 `operation_id` 调用 `ino_get_operation(..., reconcile=true)` 可执行只读对账，不重放保存。服务要求持久保存意图仍完整、原宿主实例仍在、当前绑定为目标路径、两次采集稳定、全部源码与配置事实匹配保存意图，而且 IDE 明确报告无未保存修改。任一项不能确认便保留未知状态；列工程不会为该保存结果另建可绕过锁定的工程身份。

通过后作业报告 `persistence_status=saved_copy_reconciled`，记录磁盘文件 SHA-256、原错误和对账依据，并修正保存导致的绑定变化。这个结果明确标记 `disk_reopen_verified=false`；需另行保存重开验收时，继续打开副本并核对源码、原生编译。保存发生在修改作业末尾时，索引单独标记 `rebuild_required`。若实例已重启、文件不在、存在后续修改或没有保存意图，工具不会凭路径解除锁定，也不会覆盖文件；保留材料进行人工核对。

## 索引和当前诊断

图服务恢复后，使用当前固定快照调用 `context_index_snapshot`，明确新的重建幂等键。索引失败不会触发第二次工程修改。旧快照仍可查询；`stale=false` 表示图与请求快照匹配，`current_project_stale` 另外说明它是否落后于服务最后采集的状态。查询不会隐式读取实时 IDE。

源码变化后，当前诊断指针会清除；历史失败证据仍可通过 `ino_get_diagnostics(project_id, operation_id)` 读取。没有开启自动编译时，监测不会凭空产生当前编译结论。`ino_get_changes` 的游标无效时重新捕获快照再同步。

## 资料包与证据

导出只读取固定快照。源码、来源映射、哈希清单和已校验 ZIP 一起通过目录改名发布；ZIP 路径由工具结果 `zip` 给出。以 `.pending` 结尾的目录是未发布材料，不可当作完整报告。

交接故障时保留：固定运行报告、作业 ID、工程/宿主绑定、补丁与检查点 ID、诊断、受影响副本和版本锁。模型评测只能使用合成脱敏资料；原生编译报告可能包含整份工程快照，不能直接发送给模型。

备份持久状态应先正常停止服务并保留完整 state 目录（SQLite 及其伴随文件、artifacts、bridge_commands）和对应工程副本。token、Neo4j 凭据与 OMP 模型凭据属于本机私有配置，不放入共享发布包。
